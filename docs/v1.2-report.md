# 抖音爆款文案生成工具 v1.2 版本报告

> 发布日期：2026-06-12

---

## 一、版本概述

v1.2 是抖音爆款文案生成工具的第三个正式版本，在 v1.1（导演模式 + 自定义参数）的基础上，历经五轮迭代（迭代三至迭代七），完成了**向量库检索精细化**、**知识库可视化与批量管理**、**前端布局重构**、以及**Vue 3 + FastAPI 前后端分离**四大核心升级。

**核心升级**：
- 向量库检索支持风格过滤：知识库模板与生成文案风格自动对齐
- 知识库管理全面升级：文档列表、详情查看、风格筛选、分页、批量删除
- 侧边栏双面板布局：会话列表与文档列表互斥显示，布局更紧凑
- HTML + Vue 3 + FastAPI 前端重构：彻底解决 Gradio 6 Tab 切换 Bug，引入前后端分离架构

### 2.5 迭代七：HTML + Vue 3 + FastAPI 前端重构

**问题背景**：Gradio 6.17.3 的 `tabs.select()` 事件无法正确触发 Tab 切换回调，导致知识库管理 Tab 无法切换到文档列表视图。`gr.SelectData` 兼容处理和 `inputs=[tabs]` 显式传参均无效。

**重构方案**：用 Vue 3（条件渲染 `v-if`）替代 Gradio 的 Tab 事件系统，彻底绕过上述 Bug。

| 模块 | 技术 | 说明 | 状态 |
|------|------|------|------|
| 后端 | FastAPI | `server.py`，11 个 REST API 端点，包装所有已有业务函数 | 已完成 |
| 前端 | Vue 3 CDN | `frontend/index.html` + `js/app.js` + `js/api.js`，完全复刻迭代六布局 | 已完成 |
| 样式 | CSS | `frontend/css/style.css`，橙色调设计系统 + Markdown 渲染样式 | 已完成 |
| Markdown | marked.js CDN | 文案生成结果和分镜脚本的 Markdown 渲染 | 已完成 |

**架构**：

```
python server.py 启动
  |
  +-- FastAPI (port 8000)
  |     +-- /api/*          REST API (11 个端点)
  |     +-- /*              静态文件 (frontend/)
  |
  +-- 浏览器访问 http://127.0.0.1:8000
        +-- Vue 3 (CDN) 前端
        +-- marked.js (CDN) Markdown 渲染
```

**Tab 切换修复原理**：使用 Vue 的 `activeTab` 响应式变量 + `v-if` 条件渲染。切换到"知识库管理" → `activeTab` 变为 `knowledge-base` → Vue 自动更新 DOM + 触发数据加载。完全不依赖 Gradio 事件系统。

**关键约束**：
- 0 个已有文件被修改（`main.py`、`workflow/`、`database/`、`config.py`、`tests/` 全部保留不变）
- `python main.py`（Gradio 版，端口 7860）仍可作为保留入口独立运行

### 3.2 关键设计决策

1. **检索后置过滤**：Node2 使用 `k × 3` 候选 + Python 端 style 过滤，而非 ChromaDB 原生 `where` 子句。原因是 ChromaDB 的原生过滤在某些版本中与 embedding 查询组合时有兼容性问题，后置过滤更可控
2. **分页在 Python 侧**：`list_documents()` 使用 ChromaDB `get()` 获取全部后切片分页。适用于预期数百条规模，超大规模可引入外部索引
3. **纯函数抽取**：`build_kb_list_rows()` 和 `format_kb_page_info()` 从 `create_app()` 闭包中提取为模块级纯函数，可被 Gradio 版和 FastAPI 版两套入口共用
4. **零修改已有代码**：迭代七的前端重构完全不修改已有文件，`server.py` 通过 `import` 复用所有业务逻辑
5. **LLM 调用非阻塞**：`server.py` 使用 `asyncio.to_thread()` 在线程池中运行同步的 `run_generation_workflow()`，避免阻塞 FastAPI 事件循环
6. **Tab 切换用 `v-if`**：不依赖 Vue Router，用简单的条件渲染处理两 Tab 切换，与组件生命周期配合更自然

### 3.3 REST API 设计

前后端通过 JSON API 通信，`server.py` 负责：
- 初始化全局服务（`vector_store` + `db_conn`）
- 包装已有业务函数为 HTTP 端点
- 静态文件服务（前端 `frontend/` 目录）
- CORS 中间件

前端 `api.js` 提供集中化的 `fetch()` 封装，所有 API 调用经此层统一处理错误。

## 五、已知限制

1. **Gradio Tab Bug（仅 main.py 入口）**：`python main.py`（Gradio 版）中知识库管理 Tab 切换仍存在 Bug。推荐使用 `python server.py`（Vue 3 版），该入口不受影响
2. **max_tokens 限制**：Node3 和 Node5 的 `max_tokens=2048` 仍为硬编码，文案模式 count=10 且 5 风格全选时（50 条）可能不足
3. **全局状态管理**：`server.py` 和 `main.py` 各自以不同方式初始化 `vector_store` / `db_conn`（模块级全局变量 vs 闭包捕获），缺乏统一的应用上下文
4. **Vue 前端 Bug**：迭代七快速搭建的 Vue 前端在知识库管理侧存在若干交互 Bug（风格筛选不生效、批量删除多选逻辑、列表高度等），计划在迭代八修复
5. **分镜脚本依赖 prompt 质量**：5 种导演风格各自独立 prompt，后续可按风格独立调优
6. **模拟搜索仍为静态**：Node1 仍为硬编码模板替换，未接入真实社交搜索 API
