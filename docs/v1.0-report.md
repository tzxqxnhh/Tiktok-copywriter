# 抖音爆款文案生成工具 v1.0 版本报告

> 发布日期：2026-06-10

---

## 一、版本概述

v1.0 是抖音爆款文案生成工具的首个正式版本，实现了一套完整的 AI 驱动文案生成工作流。用户输入商品名称和卖点描述后，系统通过 5 个流水线节点自动生成 3 条不同风格的抖音爆款文案，并从 5 个维度对生成结果进行评分和推荐。

## 三、技术架构

### 3.1 整体架构

```
┌─────────────────────────────────────┐
│          Gradio Web UI              │
├─────────────────────────────────────┤
│          main.py (编排层)            │
├──────┬──────┬──────┬──────┬────────┤
│Node1 │Node2 │Node3 │Node4 │Node5   │
│模拟  │知识库│LLM   │代码  │LLM     │
│搜索  │检索  │生成  │分析  │评分    │
├──────┴──────┴──────┴──────┴────────┤
│  ChromaDB    SQLite    DeepSeek API │
│  (向量库)   (会话)     (LLM)        │
└─────────────────────────────────────┘
```

### 3.2 工作流节点详解

#### Node1: 模拟搜索插件 (`workflow/node1_sim_search.py`)
- 预置 10 条基础模板覆盖 5 种风格（剧情 x3、痛点 x2、悬念 x2、干货 x2、对比 x1）
- 根据用户输入的商品名称动态替换模板占位符
- 生成带随机点赞数（5万-30万）的模拟爆款文案样本

#### Node2: 知识库检索 (`workflow/node2_knowledge.py`)
- 使用 ChromaDB 集合内置 embedding 函数进行语义检索
- 检索与用户输入最相关的 Top-K 条模板（默认 K=5）
- 返回模板文本列表供 LLM 参考

#### Node3: LLM 文案生成 (`workflow/node3_generator.py`)
- 调用 DeepSeek Chat API（temperature=0.8, max_tokens=2048）
- 综合商品信息、模拟搜索结果、知识库模板三个信息源生成文案
- 输出格式化的 3 条文案：【剧情】【痛点】【悬念】
- 具备容错解析逻辑：按风格标签解析，失败时回退到按双换行分割

#### Node4: 代码分析 (`workflow/node4_analyzer.py`)
- 字数统计：统计包含标点在内的总字符数
- emoji 计数：基于 Unicode 范围正则表达式匹配主流 emoji
- CTA 检测：13 个中文 CTA 关键词匹配（点击、购买、下单、关注等）

#### Node5: LLM 评分 (`workflow/node5_scorer.py`)
- 调用 DeepSeek Chat API（temperature=0.3, max_tokens=2048）
- 5 个评分维度：吸引力、信息量、可读性、转化潜力、情感感染力
- 每维 1-10 分，自动汇总总分
- 输出 JSON 格式结果，包含容错的正则提取逻辑

### 3.3 数据层

#### 向量数据库 (`database/vector_store.py`)
- 使用 ChromaDB PersistentClient 持久化存储
- SiliconFlow BAAI/bge-m3 模型生成 1024 维 embedding
- 自定义 SiliconFlowEmbeddingFunction 类封装 LangChain embeddings
- 支持集合自动检测和版本升级（embedding 不匹配时重建）
- 启动时自动从 `templates/copy_templates.json` 灌入 25 条预设模板
- 暴露接口：`add_document`、`add_documents`、`search`、`get_document_count`、`add_to_knowledge_base`

#### 会话管理 (`database/chat_history.py`)
- SQLite 数据库，WAL 模式提升并发性能
- 两张表：`sessions`（会话）和 `messages`（消息）
- 外键约束 + 级联删除
- 消息类型区分 `input`（用户输入）和 `result`（生成结果）

## 六、已知限制

1. **LLM 依赖**：文案生成和评分完全依赖 DeepSeek API，无网络或 API 配额耗尽时功能不可用
2. **Embedding 依赖**：知识库检索依赖 SiliconFlow API，不可用时新文档入库和检索将失败
3. **单用户设计**：当前版本面向单用户场景，未实现多用户认证和隔离
4. **无流式输出**：LLM 调用为同步阻塞模式，等待时间较长时无进度反馈
5. **模拟搜索**：Node1 为静态模板替换，未接入真实社交媒体搜索 API
6. **文件格式限制**：知识库上传仅支持 `.txt` 文件，不支持 PDF、Word 等格式
7. **emoji 检测精度**：基于 Unicode 范围的正则匹配，可能遗漏部分新版本 emoji
