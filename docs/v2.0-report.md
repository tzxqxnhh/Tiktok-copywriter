# 抖音爆款文案生成工具 v2.0 版本报告

> 发布日期：2026-06-12

---

## 一、版本概述

v2.0 是抖音爆款文案生成工具的第四个正式版本，在 v1.2（导演模式 + 知识库可视化 + 前端重构）的基础上，历经**迭代八**（Vue 前端 Bug 修复与布局优化）和**迭代九**（批量删除模式 Bug 修复），完成了前端交互体验的全面打磨。

**v2.0 核心主题**：前端体验打磨 —— 修复 v1.4 快速搭建过程中遗留的 8 个前端 Bug 和交互问题，使 Vue 3 + FastAPI 前后端分离架构在生产级质量上达到可用标准。

**版本演进路线**：

```
v1.0 (2026-06-12)    基础工作流 + 3 风格文案生成
  ↓
v1.1 (2026-06-12)    导演模式 + 自定义参数（count/styles/user_expectation/director_style）
  ↓
v1.2 (2026-06-12)    迭代三~七：向量库检索精细化 + 知识库可视化 + 布局重构 + Vue 3 前端重构
  ↓
v2.0 (2026-06-12)    迭代八~九：8 个前端 Bug 修复 + 交互打磨
```

## 二、v2.0 新增内容（迭代八 + 迭代九）

### 2.1 迭代八：Vue 前端 Bug 修复与布局优化

迭代八修复了 v1.4 Vue 前端在快速搭建过程中遗留的 6 个问题。

| 编号 | 类型 | 问题 | 修复 |
|------|------|------|------|
| KB-1 | Bug | 添加文档时前端报 `Failed to fetch` | `server.py` 中 `File(None)` 改为 `None`，修复 FastAPI 可选文件上传参数解析 |
| DL-1 | Bug | 风格筛选 Dropdown 切换后不生效 | 新增 Vue `watch` 监听 `kbStyleFilter`，替代 `@change` 事件（避免 `v-model` 更新时序问题） |
| DL-2 | Bug | 删除模式列表高度过低（仅约 9 条） | 新增 `.kb-list-container` 滚动容器（`flex: 1`），使列表撑满侧边栏可用空间 |
| DL-3 | Bug | 勾选一条即弹出确认，无法多选 | `onBatchSelectionChange` 不再自动弹出确认行，仅记录选中项 |
| DL-4 | 优化 | 退出/删除按钮混用 | 拆分为"退出"（退出删除模式）和"删除"（弹出确认行）两个独立按钮 |
| DL-5 | 优化 | 每页 40 条翻页频繁 | 每页条数从 40 改为 20，新增 `kbPageSize` computed 属性统一引用 |

### 2.2 迭代九：批量删除模式 Bug 修复

迭代九修复了批量删除模式的 2 个交互 Bug + 1 个翻页遗留问题。

| 编号 | 类型 | 问题 | 修复 |
|------|------|------|------|
| BD-1 | Bug | 进入删除模式后条目数不一致（尾页 4 条则只显示 4 条），且样式与普通模式不统一 | `enterBatchDeleteMode` 先重置 offset + reload 数据再切换模式；删除模式复用 `data-table` 表格结构，仅左侧新增勾选列 |
| BD-2 | Bug | 必须精准点击小勾选框才能选中 | 新增 `onToggleBatchRow` 方法，点击整行切换勾选；勾选框 `@click.stop` 防止重复触发 |
| — | Bug | 删除模式下翻页强制退出删除模式 | `onKbPrevPage` / `onKbNextPage` 移除 `batchDeleteMode = false`，翻页时保持删除模式 |

## 三、技术变更

### 3.1 v2.0 修改文件清单

| 文件 | 变更类型 | 迭代 | 说明 |
|------|----------|------|------|
| `server.py` | Bug 修复 | 八 | `File(None)` -> `None`（KB-1）；`KB_PAGE_SIZE` 40 -> 20（DL-5） |
| `frontend/index.html` | 重构 | 八/九 | 工具栏按钮拆分（DL-4）；`kb-list-container` 滚动容器（DL-2）；共用表格结构（BD-1）；移除 `@change`（DL-1） |
| `frontend/js/app.js` | 重构 | 八/九 | `watch` 监听器（DL-1）；`kbPageSize` computed（DL-5）；`onBatchSelectionChange` 修改（DL-3）；`onBatchDeleteClick` 新增（DL-4）；`enterBatchDeleteMode` 异步刷新（BD-1）；`onToggleBatchRow` 新增（BD-2）；翻页保持删除模式 |
| `frontend/js/api.js` | 微调 | 八 | 默认 limit 40 -> 20（DL-5） |
| `frontend/css/style.css` | 新增/清理 | 八/九 | `.kb-list-container` 新增（DL-2）；`.batch-checkboxes` 样式移除（BD-1） |

### 3.2 关键设计决策

1. **共用表格结构（BD-1）**：删除模式不再使用独立的 `batch-checkboxes` 容器，改为在 `data-table` 每行左侧动态增加勾选列。`v-if="batchDeleteMode"` 控制勾选列的显示，保证两种模式的视觉一致性
2. **Watcher 替代 @change（DL-1）**：Vue 3 的 `v-model` 和 `@change` 在同一 `<select>` 上存在事件触发顺序的不确定性，使用 `watch` 在数据更新后触发可保证 `kbStyleFilter` 已是新值
3. **点击行切换勾选（BD-2）**：`@click="batchDeleteMode ? onToggleBatchRow(idx) : onKbRowClick(idx)"` 根据模式分流行点击行为。勾选框所在 `<td>` 使用 `@click.stop` 阻止冒泡，避免 v-model 和行点击重复切换
4. **翻页保持模式**：`onKbPrevPage` / `onKbNextPage` 不再设置 `batchDeleteMode = false`，仅清空 `batchSelectedIds` 和 `showDeleteConfirm`（避免跨页误删）
5. **分页大小集中管理**：新增 `kbPageSize` computed 属性（返回 20），`loadKbData`、`kbIsLastPage`、翻页方法统一引用，消除魔法数字

## 五、已知限制

1. **Gradio Tab Bug（仅 main.py 入口）**：`python main.py`（Gradio 版）中知识库管理 Tab 切换仍存在 Bug。推荐使用 `python server.py`（Vue 3 版），该入口完全不受影响
2. **max_tokens 限制**：Node3 和 Node5 的 `max_tokens=2048` 仍为硬编码，文案模式 count=10 且 5 风格全选时（50 条）可能不足
3. **全局状态管理**：`server.py` 和 `main.py` 各自以不同方式初始化 `vector_store` / `db_conn`（模块级全局变量 vs 闭包捕获），缺乏统一的应用上下文
4. **模拟搜索仍为静态**：Node1 仍为硬编码模板替换，未接入真实社交搜索 API
5. **错误处理兜底逻辑**：Node3 和 Node5 的 try/except fallback 在各处复制粘贴，缺乏统一的容错策略模块
